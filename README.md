Система медицинских напоминаний. Программный комплекс для контроля приема лекарственных препаратов пациентами с хроническими заболеваниями.

**Стек:** Python 3.11, PostgreSQL 16, Redis, Docker Compose, psycopg2-binary, redis-py.

---

## Структура проекта

```
.
├── kr/                       # Итоговые материалы контрольной работы
│   ├── db/                   # SQL-скрипты инициализации и наполнения БД

│   ├── src/                  # Исходный код приложения (Service/Repository layers)
```

## Запуск системы

### Шаг 1. Развертывание баз данных

Запуск контейнеров PostgreSQL и Redis через Docker Compose:
```bash
docker compose up -d
```

### Шаг 2. Инициализация данных

Создание базы данных и применение схемы из материалов проекта:
```bash
docker exec -i medical_db_postgres psql -U postgres -c "CREATE DATABASE medical_reminders;" || true
docker exec -i medical_db_postgres psql -U postgres -d medical_reminders < kr/db/init_db.sql
```

### Шаг 3. Настройка окружения

Создание виртуального окружения и установка необходимых библиотек:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Шаг 4. Запуск приложения

Запуск основного модуля информационной системы:
```bash
python3 kr/src/main.py
```

## Функционал приложения

Приложение реализовано в виде консольного интерфейса и предоставляет следующие возможности:

1. **Управление пациентами:** CRUD операции над данными пациентов.
2. **Управление назначениями:** Создание и редактирование медицинских назначений. Реализован вывод данных с использованием SQL JOIN для отображения имен пациентов вместо их идентификаторов.
3. **Работа с NoSQL (Redis):** 
   - Управление сессиями пользователей с использованием TTL.
   - Кэширование справочной информации о препаратах для ускорения доступа.
4. **Функциональные отчеты:**
   - Формирование полного графика приема лекарств для конкретного пациента.
   - Расчет статистики популярности препаратов.

## Архитектура

Приложение построено на базе многослойной архитектуры с применением паттерна **Repository**:
- **UI Layer:** Обработка ввода пользователя и вывод данных в консоль.
- **Service Layer:** Бизнес-логика и координация взаимодействия между репозиториями.
- **Repository Layer:** Инкапсуляция SQL и NoSQL запросов, изоляция доступа к данным.
- **Data Layer:** PostgreSQL (структурированные данные) и Redis (оперативные данные/кэш).
